<TLDR>
I had built a corpus map, a 2,050-question index and a six-mode command palette — and then noticed that my own homepage's "Explore the site" section listed six of the site's eight destinations, silently omitting two of them. This article is the cheap half of that story: a floating chat bubble that opens the question search from any page, the missing homepage cards, and a first-visit hint. Plus the small pub-sub trick that guarantees two independent floating dialogs never end up open at the same time.
</TLDR>

There is a particular kind of embarrassment reserved for people who build things alone. I had spent weeks on features I was genuinely proud of: an interactive <Link to="/blog/docusaurus-blog-map">map of the whole blog</Link>, a <Link to="/blog/docusaurus-ask-my-blog">question index</Link> generated by a local model, a <Link to="/blog/docusaurus-command-palette">command palette</Link> with six modes.

Then I opened my own homepage the way a first-time visitor would, and counted. The "Explore the site" section had six cards: Blog, Series, Tags, Repositories, Archive, About. The navbar had eight entries. The two missing ones were, of course, Map and Ask My Blog — the only two that were not standard Docusaurus.

Nobody had hidden them. They had simply never been added, because I already knew they existed.

## What Changed

Three things, none of them a new feature:

```plaintext
1. The homepage grid                2. A floating bubble        3. A first-visit pill
   ┌──────┬──────┬──────┐              ┌────────────────┐          ┌─────────────────┐
   │ Blog │Series│ Tags │              │ 🦫 Ask my blog │          │ Press ⌘K to     │
   ├──────┼──────┼──────┤              ├────────────────┤          │ search      ✕   │
   │ Map  │ Ask  │Repos.│              │ [Ask a questi…]│          └─────────────────┘
   ├──────┼──────┼──────┤              │  › How do I …  │
   │Archiv│About │      │              │  › What is …   │
   └──────┴──────┴──────┘              └────────────────┘
     ↑ two new cards                     bottom-right, every page
```

The bubble is the interesting one, because it is the **third** way into exactly the same question index: `Ctrl+K` then `?`, the standalone `/faq` page, and now a chat-shaped button that follows the reader around. Same corpus, same ranking, same results — three doors.

## Why Three Doors Is Not Redundancy

I resisted the bubble for a while, on the grounds that the palette already did the job. That was wrong, and here is the reasoning that changed my mind:

- **Each door serves a different reader.** The palette serves people who already know it exists. `/faq` serves search engines and people who want to browse a topic. The bubble serves the reader who is stuck in the middle of an article and would never think to press a keyboard shortcut.
- **A floating button is the one affordance everyone already understands.** Nobody needs to be taught what a chat bubble in the corner does. That is precisely why it is worth spending a corner on — and why the panel header wears the same <Link to="/blog/docusaurus-easter-eggs">meerkat mascot</Link> that shows up everywhere else on this site.
- **It costs almost nothing to add.** The bubble does not reimplement search — it mounts the existing search component inside a panel. About 150 lines, most of them focus management.
- **The expensive part was already paid for.** The question corpus, the ranking, the lazy fetch: all of it existed. Adding an entry point to a built feature is the highest-leverage work available, and it is the work that gets skipped.

## Building the Bubble

The component is deliberately thin. When the panel is closed, nothing search-related is mounted at all — so the 468 KB question corpus is still only fetched by a reader who actually opens it:

  <Snippet filename="src/components/AskMyBlogWidget/styles.module.css" source="src/components/AskMyBlogWidget/styles.module.css" defaultOpen={false} />
</ProjectSetup>

It is mounted once per page, in the same `Layout` swizzle that mounts the palette:

```javascript title="src/theme/Layout/index.js"
export default function LayoutWrapper(props) {
  return (
    <Layout {...props}>
      {props.children}
      <CommandPalette />
      <CommandPaletteHint />
      <AskMyBlogWidget />
    </Layout>
  );
}
```

One layout decision worth copying: the bubble reserves a **fixed slot stacked above** the <Link to="/blog/docusaurus-go-top">scroll-to-top button</Link>'s corner, rather than detecting that button's presence at runtime. Scroll-to-top is not mounted on every page, and a bit of empty space above it when it is absent is completely harmless — far more harmless than two floating buttons racing to occupy the same 60 pixels.

## The Two-Overlays Problem

The palette and the bubble panel are independent floating dialogs, each openable from several places, and neither knows the other exists. Open one while the other is open and you get two modals stacked, two focus traps fighting, and two <kbd>Esc</kbd> handlers.

The fix is eight lines, and it lives in the palette's own bus module — so neither component has to import the other:

```javascript title="src/components/CommandPalette/paletteBus.js"
let activeCloser = null;

export function setActiveOverlay(closeFn) {
  if (activeCloser && activeCloser !== closeFn) activeCloser();
  activeCloser = closeFn;
  return () => {
    if (activeCloser === closeFn) activeCloser = null;
  };
}
```

Each dialog calls `setActiveOverlay(close)` when it opens, and calls the cleanup function it gets back when it closes. Whichever opens second closes whichever was open first. Adding a third overlay later requires changing nothing.

## Under the Hood (skip this if you just want the bubble)

### A hint that is allowed to appear exactly once

Both the palette's pill and the bubble's pulse ring are first-visit hints, and both follow the same three rules:

- The `localStorage` flag is written **when the hint is shown**, not when it is dismissed. A visitor who ignores it does not get it again on their next page.
- The delays are staggered — the palette's pill at 4 or 10 seconds, the bubble's pulse at 15 — so the two never animate in together and read as a pop-up.
- The pulse ring is removed entirely under `prefers-reduced-motion`, not just slowed down.

The palette's delay is deliberately different per page type, and the reason is worth stating: 10 seconds on an article exists so the pill never interrupts someone who has just started reading. The homepage has no reading to interrupt and is where visitors bounce fastest, so it gets 4 seconds — still long enough not to look like a load-time pop-up.

```javascript title="src/components/CommandPalette/Hint.js"
function delayFor(pathname) {
  if (HOME_PATH.test(pathname)) return HOME_DELAY_MS;
  if (ARTICLE_PATH.test(pathname)) return ARTICLE_DELAY_MS;
  return null;
}
```

Returning `null` — rather than a large number — is what makes "this path shows nothing" a distinct, readable state instead of a delay you have to squint at.

### The homepage cards, and the comment that matters more than the code

Adding two cards is two objects in an array. The part that stops the bug from coming back is the comment placed above that array:

```javascript title="src/data/home_cards.js"
/**
 * Kept in the same order as the navbar items in `docusaurus.config.js`, and covering the same
 * destinations: this section is the visual restatement of the navbar for a visitor who scrolls
 * rather than reads the top bar, so a destination present in one and absent from the other
 * is a bug.
 */
```

Two lists that must agree and no rule saying so is how they drifted apart in the first place. Writing the invariant down is cheaper than any test I could have added.

The grid itself got a guard at the same time. The card images are square, but the layout no longer *depends* on that being true:

```css title="src/components/HomeCards/styles.module.css"
.cardImage {
  aspect-ratio: 1 / 1;
  object-fit: cover;
}
```

Verified at one, two and three columns — with eight cards, three columns give rows of 3-3-2 and one empty cell at the end, which is a perfectly ordinary grid.

### The card I decided not to build

The original plan had a ninth card: "Search everything", opening the command palette. I dropped it, and the reasoning is the useful part.

By the time I got to it, the swizzled search bar had become a real, permanently visible search box in the navbar — showing the article count and the shortcut, on every page including the homepage. A card pointing at the same palette would have been a third reminder of one entry point (navbar, footer, card). The cost was not zero either: the cards component only knows how to render a `<Link>`, so it would have needed to learn a non-link action, and I would have had to produce a ninth illustration in a set where all eight are meerkat drawings — a "press ⌘K" graphic would have looked pasted in.

Three doors into the question index: yes, because they serve different readers. Three reminders of the same door: no.

## Conclusion

The features in this series took weeks. Making them findable took an afternoon, and it is entirely possible that the afternoon mattered more.

There is a failure mode specific to building your own tools: you are the one user who can never evaluate discoverability, because you cannot un-know where things are. The only fix I have found is mechanical — count the entry points, compare the lists that are supposed to agree, and write the invariant in a comment so the next drift is visible.

And when in doubt, put a button in the corner. Everybody knows what it does.
