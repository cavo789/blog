# 🦫 ShakeEasterEgg

A tiny, self-contained Docusaurus/React component that listens for a phone
shake (via the `devicemotion` sensor) and rewards the visitor with the site's
meerkat mascot, startled and flailing, taking over the full screen for a
couple of seconds.

## 🚀 Features

- 📱 Listens globally for a shake gesture on devices exposing `devicemotion`
- 🦫 Shows a huge, centered, animated meerkat (pop-in + tremble) over a dark
  backdrop, then fades out on its own
- 👆 Tap anywhere to dismiss early
- 📳 Best-effort haptic buzz via `navigator.vibrate()` where supported
- ♿ Respects `prefers-reduced-motion` (the meerkat appears without the
  pop/tremble animation)
- 🪶 No props, no configuration — mount once and forget

## 📦 Installation

This component is already wired into the site globally via
[`src/theme/Root.js`](../../theme/Root.js), so it renders on every page
without further setup:

```jsx
import ShakeEasterEgg from "@site/src/components/ShakeEasterEgg";

export default function Root({ children }) {
  return (

      {children}
```

## 🧠 How it works

- `index.js` accumulates `devicemotion` samples (`accelerationIncludingGravity`)
  and computes the "jerk" (rate of change of acceleration summed across the
  three axes) between consecutive samples. A jerk spike above
  `SHAKE_JERK_THRESHOLD`, outside the `COOLDOWN_MS` window, triggers the
  overlay.
- The overlay is a full-viewport `<button>` (so tapping anywhere dismisses
  it) showing
  [`suricate_scared.webp`](../../../static/img/meerkat/suricate_scared.webp)
  over a dark radial-gradient backdrop.
- Display goes through three phases (`hidden` → `visible` → `leaving`) so the
  exit gets a CSS fade instead of popping out abruptly, whether it ends by
  timeout or by tap.

## ⚠️ Known limitation — iOS is intentionally unsupported

iOS Safari 13+ requires an explicit `DeviceMotionEvent.requestPermission()`
call tied to a user gesture (a tap) before it will fire `devicemotion` events
at all — it cannot be requested proactively on page load, and the call only
exists on iOS, never on Android. This component does not implement that
permission dance, so on iOS the shake simply never triggers (silent no-op,
no error) — and this is a deliberate decision, not an unfinished one. Every
other easter egg on this site is invisible until a visitor stumbles onto it
on purpose (a key sequence, a hidden comment, a tab left in the background);
satisfying `requestPermission()`'s user-gesture requirement would mean either
a visible "enable this" button (breaking that rule) or firing the request on
the visitor's very first unrelated tap (a native permission dialog appearing
out of nowhere). Neither fits, so this ships Android-only, permanently, by
choice — not a gap waiting to be filled.

Android Chrome needs no `requestPermission()` call, but has its own per-site
**Motion sensors** permission (Site info → Permissions) that can be blocked —
in that state `devicemotion` still fires, but
`event.accelerationIncludingGravity` comes back `null`, silently. If the
shake does nothing on an Android device, check that setting before assuming
a code bug; `navigator.permissions.query({ name: "accelerometer" })` reports
its state (`"granted"` / `"denied"` / `"prompt"`).

## 🎨 Customization

- **Sensitivity**: tune `SHAKE_JERK_THRESHOLD` in `index.js` — lower it if a
  deliberate shake doesn't trigger the egg, raise it if normal handling
  triggers it by accident. Not yet tuned against a physical device.
- **Timing**: `VISIBLE_DURATION_MS`, `EXIT_DURATION_MS` and `COOLDOWN_MS` in
  `index.js` control how long the overlay stays up, how fast it fades, and
  how soon it can retrigger. Keep `EXIT_DURATION_MS` in sync with the
  `overlay-out` keyframes duration in `styles.module.css`.
- **Sprite**: swap the `scaredImg` import for any other transparent-background
  meerkat pose from `static/img/meerkat/`.
