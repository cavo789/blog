## Que vient-il de se passer {#what-just-happened}

Cette unique commande a demandé à Docker de lire le fichier `compose.yaml` et, à partir de là&nbsp;:

1. un réseau `joomla_default` est créé,
2. le container `joomla-joomladb-1` est créé (c'est votre serveur de base de données) et
3. le container `joomla-joomla-1` est créé lui aussi (c'est votre service Joomla).

Les deux containers partagent le réseau, c'est comme ça que Joomla peut joindre la base de données par son nom de service. La suite de cet article explique ce fichier ligne par ligne, puis va beaucoup plus loin&nbsp;: persister votre site sur le disque, lancer des commandes CLI, changer de port, passer à PostgreSQL ou MariaDB.

## Docker compose {#docker-compose}

Quand vous avez besoin de plusieurs services (Apache doit pouvoir communiquer avec PHP et PHP doit pouvoir demander des données à MySQL), vous devez configurer un fichier particulier appelé `compose.yaml`. Ce fichier doit être placé à la racine du projet et va définir la liste des services nécessaires ainsi que la manière dont ils collaborent.

Vous trouverez un exemple de fichier `compose.yaml` sur la page de description de l'image Joomla&nbsp;: [https://hub.docker.com/\_/joomla](https://hub.docker.com/_/joomla) _cherchez `docker-compose` sur cette page._

### Pourquoi des noms joomla-joomlaxxx {#why-joomla-joomlaxxx-names}

Docker a donc nommé votre projet en utilisant le nom du dossier (`joomla`) concaténé au nom du service (regardez le fichier `compose.yaml`&nbsp;: nous avons deux services, un appelé `joomladb` et un appelé `joomla`). Éditez le fichier `compose.yaml` et ajoutez une ligne avec `name: xxxx` où `xxxx` est le nom de votre choix. <Terminal typewriter>$ docker compose up --detach</Terminal>

Retournez sur le site, rafraîchissez la page et le site, ah, ne répond pas encore. Attendez un peu... encore un peu... et après un certain temps, le site sera là. Pourquoi&nbsp;?

Docker doit (re)démarrer deux services, celui de Joomla et le serveur de base de données. L'initialisation des deux peut prendre quelques secondes, et le service de base de données doit être en route pour que Joomla puisse poursuivre son initialisation.

Vous pouvez le voir en lançant `docker compose logs --follow` (appuyez sur <kbd>CTRL</kbd>+<kbd>C</kbd> pour quitter).

<Terminal typewriter>$ docker compose logs --follow</Terminal>

Une fois Joomla prêt, vous retrouverez l'assistant d'installation de Joomla... comme la première fois. Donc, en lançant `docker compose down`, vous avez perdu votre travail.

<Terminal typewriter>$ docker compose down</Terminal>

<AlertBox variant="danger">
Comme mentionné plus haut, tout se passe en RAM. En arrêtant un container Docker, vous perdez tout ce qui n'est pas sauvegardé sur votre ordinateur. C'est parfait pour jouer/apprendre mais pas ce que vous attendez quand vous développez un vrai site.

</AlertBox>

<AlertBox variant="info">
Rappelez-vous de la modification faite plus tôt. Nous avions ajouté le nom <Var name="name">kingsbridge</Var> comme nom de projet dans votre fichier `compose.yaml`, et nous avions nommé les deux containers. Vous pouvez voir qu'après avoir relancé `docker compose up`, ce n'est plus `joomla-joomlaxxxx` mais <Var name="name">kingsbridge</Var>-app et <Var name="name">kingsbridge</Var>-db. C'est parce que les modifications faites dans le fichier yaml ne sont prises en compte qu'après une commande `down / up`. Si vous modifiez le fichier yaml, vous devez redémarrer vos containers Docker.

</AlertBox>

Le dossier `/var/www/html` du service Joomla doit être synchronisé avec le sous-dossier `site_joomla` sur votre ordinateur. C'est pour le site Joomla.

Et le dossier `/var/lib/mysql` du service MySQL doit être synchronisé avec votre sous-dossier local `db`.

Les deux lignes `user: ${UID:-1000}:${GID:-1000}` sont vraiment importantes et indiquent à Docker de réutiliser votre utilisateur local (celui de votre session Linux).

<AlertBox variant="highlyImportant" title="L'UID/GID de l'utilisateur">
Cette partie est cruciale&nbsp;: si vous tapez `id -u` et `id -g` sous Linux, vous obtiendrez votre propre user_id et group_id (autrement dit UID et GID). La plupart du temps, ce sera `1000` pour les deux mais... parfois non.

La syntaxe `user: ${UID:-1000}:${GID:-1000}` signifie d'utiliser `1000` comme valeur par défaut sauf si les variables système `UID` et `GID` existent, auquel cas on utilise leurs valeurs.

</AlertBox>

<AlertBox variant="info" title="La synchronisation a un coût">

Cela dit, la différence de vitesse n'est pas flagrante en temps normal. Si vous êtes développeur et que vous écrivez des centaines voire des milliers d'enregistrements, vous verrez une différence notable.

</AlertBox>

## Lancer une commande CLI {#start-a-cli-command}

Quand vous travaillez sur un site Joomla, vous avez parfois besoin de lancer une commande PHP comme `php joomla.php`.

Pour cela, vous devez démarrer une _session shell interactive_ dans le container Joomla.

Vous vous souvenez du nom de votre service Joomla&nbsp;? Sinon, rouvrez simplement le fichier `compose.yaml`.

<Snippet
  filename="compose.yaml"
  source="./files/compose_service_joomla.yaml"
  defaultOpen={true}
/>

Le nom de votre service Joomla est `joomla` (et `joomladb` est le nom de votre service de base de données).

Nous savons maintenant tout ce qu'il faut&nbsp;: pour lancer une session shell interactive dans le container Joomla, il suffit de lancer `docker compose exec joomla /bin/sh` pour _sauter_ dans le container Joomla (_et `docker compose exec joomladb /bin/sh` pour le container de la base de données_).

<Terminal typewriter>$ docker compose exec joomla /bin/sh</Terminal>

Rembobinons quelques secondes parce que c'est compliqué à saisir.

Sur votre ordinateur, dans votre console Linux, si vous tapez `pwd` pour connaître le dossier courant, vous verrez `/tmp/joomla` puisque c'est le répertoire utilisé dans ce tutoriel.

Ensuite, nous sautons dans le container Docker Joomla en lançant `docker compose exec joomla /bin/sh` et, vous le voyez, nous n'avons plus un prompt qui commence par `>` mais par `$`, et ce n'est pas la seule différence. Si maintenant nous relançons `pwd`, nous ne sommes plus dans votre dossier `/tmp/joomla` mais dans `/var/www/html`.

Ça peut rendre fou mais... quand vous entrez dans le container Docker, vous n'êtes _plus_ sur votre ordinateur, vous êtes virtuellement sur un autre ordinateur, le container. Dans cet _ordinateur_, le dossier courant est donc `/var/www/html`. En tapant `exit`, vous quittez le container, vous revenez sur votre ordinateur et dans le dossier `/tmp/joomla`.

<Terminal typewriter source="./files/terminal-2.txt" />

## Utiliser un alias {#using-alias}

Docker démarrera toujours votre projet sur votre localhost et sur un port du type `http://127.0.0.1:`<Var name="port">8080</Var>.

## Utiliser un autre port {#using-another-port}

Imaginez que vous ayez un autre projet, pas `Kingsbridge` cette fois. Pouvez-vous faire tourner plusieurs projets Docker en même temps&nbsp;? Oui, bien sûr&nbsp;!

Il faut juste veiller à utiliser un autre port, non utilisé.

Prenons le fichier `compose.yaml` du projet `shiring`

<Snippet filename="compose.yaml" source="./files/compose_shiring.yaml" />

Nous allons utiliser le port `8081` pour ce projet et, dans votre fichier hosts, nous ajouterons `127.0.0.1 shiring`.

Donc, maintenant et en même temps, nous pouvons accéder à `http://`<Var name="name">kingsbridge</Var>`:`<Var name="port">8080</Var> et à `http://shiring:8081` sans conflits puisque nous avons utilisé un numéro de port distinct.

Kingsbridge peut être un site Joomla 4.4 / PHP 7.4 tandis que shiring tourne sur Joomla 5.0 / PHP 8.2, sans le moindre conflit. **Et c'est d'une simplicité stupéfiante, quand on repense à la façon dont on travaillait avant Docker.**

<AlertBox variant="info">
Utiliser un autre port n'est pas obligatoire. Vous pouvez avoir plusieurs sites sur le même port, par exemple <Var name="port">8080</Var>. Mais dans ce cas, vous ne pourrez pas les utiliser en même temps. Vous pouvez démarrer le premier et, en essayant de démarrer le second, Docker dira *port already in use*. Ce n'est pas un problème&nbsp;; lancez simplement `docker compose stop` pour le premier afin de libérer le port, puis démarrez le second.

<Terminal typewriter>$ docker compose stop</Terminal>

</AlertBox>

<AlertBox variant="note">
  Dans cet article, j'utilise le port <Var name="port">8080</Var> parce que Joomla l'utilise
  dans son fichier `compose.yaml` par défaut. Vous n'êtes pas obligé de le
  garder, vous pouvez parfaitement utiliser `80` et pas <Var name="port">8080</Var>. Dans mon
  travail quotidien, j'utilise les ports `80`, `81`, `82`, `83`, ... en variant
  le second chiffre pour mes projets.
</AlertBox>

## Vous préférez PostgreSQL ou MariaDB {#did-you-prefer-postgresql-or-mariadb}

Jusqu'ici, nous avons choisi MySQL comme gestionnaire de base de données. Notre fichier `compose.yaml` est celui, légèrement modifié, que l'on trouve sur [https://hub.docker.com/\_/joomla](https://hub.docker.com/_/joomla).

Pourriez-vous opter pour autre chose que MySQL&nbsp;? Bien sûr, tant que Joomla supporte ce système (voir [https://manual.joomla.org/docs/next/get-started/technical-requirements/](https://manual.joomla.org/docs/next/get-started/technical-requirements/)).

Il suffit de remplacer le service `joomladb`, de ne plus utiliser `mysql` mais celui que nous voulons.

<Details label="Utiliser PostgreSQL">

Nous devons aussi changer quelques variables&nbsp;:

- L'utilisateur par défaut de la base doit être précisé, ce sera par exemple `postgres`,
- Nous devons aussi définir le nom de la base dans les deux services&nbsp;; nous l'appellerons `joomla_db` et
- Nous devons indiquer à Joomla que nous utilisons PostgreSQL, il faut donc mettre `JOOMLA_DB_TYPE` à `pgsql` (soit `mysql`, soit `pgsql`).

## Informations complémentaires {#extra-information}

### Le container sera redémarré par Windows {#the-container-will-be-restarted-by-windows}

Si vous éteignez votre ordinateur alors qu'un ou plusieurs containers tournent encore, Docker les relancera au démarrage suivant.

Autrement dit, la prochaine fois que vous démarrez votre ordinateur, votre site sera toujours accessible et vous n'aurez pas une seule commande à lancer. C'est tellement simple&nbsp;!

### Travailler avec Windows {#working-with-windows}

Imaginez que vous soyez dans votre console (par exemple après un `cd /tmp/joomla` dans la console Linux) et que vous vouliez ouvrir le site avec Visual Studio Code, déjà installé sur votre machine Windows.

C'est facile&nbsp;: lancez simplement `code .` pour ouvrir le dossier courant, donc votre projet, dans vscode.

Autre cas d'usage&nbsp;: vous voulez démarrer l'Explorateur Windows et naviguer dans la structure de votre projet. Là aussi c'est possible, lancez simplement `explorer.exe .` pour l'ouvrir sur le répertoire courant. Voyez mon article «&nbsp;[Ouvrir votre dossier Linux dans l'Explorateur Windows](/blog/wsl-windows-explorer)&nbsp;» pour en savoir plus sur cette fonctionnalité.

## Conclusion {#conclusion}

Ce que je préfère dans cette approche, ce n'est pas la vitesse — c'est qu'un site Joomla devient un *dossier*. Un `compose.yaml`, deux sous-dossiers, et vous pouvez en avoir cinq côte à côte, chacun sur son port, chacun avec sa base, sans qu'aucun ne puisse casser les autres. Supprimer un site, c'est supprimer un dossier.
