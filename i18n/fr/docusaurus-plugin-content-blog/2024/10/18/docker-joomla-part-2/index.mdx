## Pourquoi ça fonctionne {#why-it-works}

- `compose.yaml`, `.env` et `makefile` forment ensemble un point de configuration unique : un
  fichier à modifier pour la version de Joomla ou de PHP, un autre pour le numéro de port et le nom
  du projet, et des cibles `make` pour que personne n'ait à retenir les incantations `docker compose`
  brutes.
- `depends_on` + `healthcheck` dans `compose.yaml` font attendre Joomla jusqu'à ce que la base de
  données soit réellement prête avant de lancer sa propre installation — plus de crash au démarrage.
- Comme toute la configuration tient dans trois petits fichiers, la même recette passe à l'échelle
  avec plusieurs projets isolés (versions différentes de Joomla/PHP/MySQL) sur la même machine,
  comme le montrent les sections *Configuration avancée* et *Démarrer trois projets différents*
  ci-dessous.

## Créer les trois fichiers de configuration {#create-the-three-configuration-files}

Contrairement à l'article [Create your Joomla website using Docker - Part 1](/blog/docker-joomla), où j'avais commencé par expliquer quelques concepts avant d'entrer dans le sujet, faisons l'inverse ici : partons des trois fichiers que nous allons utiliser, puis voyons comment ils fonctionnent. N'essayez pas trop de comprendre le contenu des fichiers ; nous y reviendrons plus tard.

Créez les trois fichiers dans un dossier sur votre disque dur pour le moment (par exemple dans `/tmp/joomla`), afin d'aller vite à l'essentiel : créer un site Joomla avec une seule ligne de commande à exécuter sur votre ordinateur.

### Notre fichier d'orchestration : compose.yaml {#our-orchestration-file-composeyaml}

Il nous faut un fichier qui explique à Docker comment nous voulons configurer Joomla et, aussi, le type de base de données souhaité.

Notre fichier d'orchestration va également indiquer à Docker que nous voulons que le site Joomla soit persistant, c'est-à-dire que les fichiers soient enregistrés sur notre disque dur. Idem pour la base de données.

Nous devons faire ça pour que, si nous **supprimons** volontairement le container Docker afin de libérer de la mémoire par exemple, le site Joomla reste sauvegardé sur le disque. Ainsi, la prochaine fois que nous réveillerons notre site, les fichiers et les tables de la base seront restaurés.

<AlertBox variant="info" title="Persistance">
Il existe deux types de persistance : celle gérée nativement par Docker (*volumes internes*) ou celle où nous voyons les fichiers dans le dossier de notre projet (*volumes montés*). Nous opterons pour la seconde. Voyez mon article [Using volumes with Docker, use cases](/blog/docker-volumes) si vous voulez en savoir plus.

</AlertBox>

Nous allons aussi définir une dépendance (basée sur `depends_on` et `healthcheck`) : Joomla doit attendre que le serveur de base de données soit prêt avant de démarrer son installation (en effet, si l'installateur Joomla essaie d'accéder à MySQL avant même que le système soit chargé, notre projet plantera pendant le chargement des containers).

Comme vous le voyez, notre fichier `compose.yaml` est d'une importance capitale pour bien définir notre projet.

<AlertBox variant="note">
Ces derniers mois, le nom du fichier à utiliser est passé de `docker-compose.yaml` à `compose.yaml` ; l'ancien nom est toujours supporté pour l'instant, mais autant utiliser le nouveau. Voyez [docs.docker.com](https://docs.docker.com/compose/intro/compose-application-model/#the-compose-file) si vous voulez plus d'infos sur ce changement.

</AlertBox>

Nous allons aussi utiliser un fichier de configuration nommé `.env` (qui n'est jamais rien de plus qu'un bête dictionnaire de clés - valeurs) pour différencier nos projets.

Créez un deuxième fichier appelé `.env` avec ce contenu :

<Snippet filename=".env" source="./files/.env" />

Utiliser un fichier `.env` est vraiment pratique : vous n'avez plus besoin de modifier le fichier `compose.yaml`, qui peut rester standard pour tous vos projets.

Si vous avez besoin de deux sites Joomla ou plus (vous êtes une agence web qui commence à utiliser Docker pour son développement), vous n'aurez à modifier que le fichier `.env` en changeant le `WEB_PORT` (chaque projet doit avoir son port unique) et vous mettrez probablement aussi à jour `PROJECT_NAME`, par exemple avec le nom de votre client.

<AlertBox variant="info">
`WEB_PORT`, `PROJECT_NAME`, ... ne sont que des *variables*. Si vous regardez à nouveau le contenu du `compose.yaml` que vous venez de copier/coller, vous retrouverez ces variables, par exemple sur la ligne `image: joomla:${JOOMLA_VERSION:-latest}`.

La syntaxe `${XXX:-yyy}` signifie : si la variable existe, utilise-la (la partie `XXX`), sinon utilise une valeur par défaut (la partie `yyy`).

Donc ici, si `JOOMLA_VERSION` existe, et c'est le cas dans notre fichier `.env`, alors sa valeur est utilisée. Nous aurons donc `image: joomla:5.2.0-php8.3-apache`. Si `JOOMLA_VERSION` était absente de notre `.env`, alors nous utiliserions `latest` et donc `image: joomla:latest`.

</AlertBox>

## Réveillons Joomla... {#lets-wake-up-joomla}

Nous voici au cœur du sujet : nous aimerions voir un beau site Joomla tout neuf. Est-ce possible en une seule commande, et même sans rien installer à la main ?

La réponse est « oui » et `make up` fera la magie.

Dans votre console, lancez simplement `make up`, et patientez une minute. La toute première fois, vous obtiendrez la sortie console montrée en haut de cet article.

Qu'est-ce que ça veut dire ? Docker a récupéré (_pulled_) depuis Internet nos services `joomla` et `joomladb` (autrement dit, il a téléchargé le CMS Joomla (avec PHP et Apache) et MySQL).

En lançant ensuite la commande ci-dessous (ou juste `docker container list` pour obtenir toutes les colonnes), vous obtiendrez la liste des containers en cours d'exécution :

<Terminal typewriter source="./files/terminal-2.txt" />

Comme on le voit, youpi !, nous avons nos deux services (des containers nommés) qui sont Joomla et MySQL, et tous les deux sont _Up_ (voyez la colonne `Status`). On voit que Joomla utilise le port `8080` et MySQL le port `3306`.

<AlertBox variant="info">
Le port `8080` est celui spécifié dans notre `.env` (variable `WEB_PORT`) et, pareil pour MySQL, il utilise le port `3006` parce que c'est celui que nous avons défini (`MYSQL_PORT`).

Notez que `3306` est le port standard de MySQL.

</AlertBox>

### ... ou demandons-lui de s'endormir (on garde les containers) {#-or-lets-ask-him-to-fall-asleep-keep-containers}

La commande inverse de `make up` est `make stop`. L'action `stop` arrêtera nos containers Joomla et MySQL (comprenez `les faire dormir`) mais sans supprimer les fichiers (votre site et votre base) de votre disque dur. En relançant `make up`, vous les retrouverez. `up` et `stop` sont comme un interrupteur.

<Terminal typewriter>$ make stop</Terminal>

### ... ou demandons-lui de supprimer les containers (libérer plus de mémoire) {#-or-lets-ask-him-to-remove-containers-free-more-memory}

La commande `make down` va arrêter les containers et les supprimer. Mais dans notre cas, nous aurons toujours les fichiers sur notre disque dur, donc nous ne perdrons pas notre site.

<Terminal typewriter>$ make down</Terminal>

### ... ou demandons-lui de se suicider (supprimer les containers et les fichiers) {#-or-lets-ask-him-to-suicide-remove-containers-and-files}

La commande `make reset` arrêtera les containers mais supprimera aussi les fichiers sur le disque.

<Terminal typewriter>$ make reset</Terminal>

<AlertBox variant="danger">
En lançant `make reset`, vous perdrez tout et serez prêt à créer un nouveau site.

</AlertBox>

## Configuration avancée pour Joomla {#advanced-configuration-for-joomla}

L'image Docker officielle de Joomla est maintenue par la communauté Joomla sur Docker Hub : [https://hub.docker.com/\_/joomla](https://hub.docker.com/_/joomla).

Vous y retrouverez une liste de _tags_, c'est-à-dire une liste de versions que vous pouvez installer avec Docker, mais vous y trouverez aussi une section **How to use this image** et celle-là est vraiment utile.

Voici la liste des variables supportées par Joomla fin septembre 2024 :

| Nom de la variable        | Description                                                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `JOOMLA_DB_HOST`          | Par défaut, l'IP et le port du container mysql lié                                                                 |
| `JOOMLA_DB_USER`          | `root` par défaut                                                                                                  |
| `JOOMLA_DB_PASSWORD`      | Par défaut, la valeur de la variable d'environnement `MYSQL_ROOT_PASSWORD` du container mysql lié                  |
| `JOOMLA_DB_PASSWORD_FILE` | Chemin vers un fichier contenant le mot de passe de la base                                                        |
| `JOOMLA_DB_NAME`          | `joomla` par défaut                                                                                                |
| `JOOMLA_DB_TYPE`          | `mysqli` par défaut ; options : `mysqli`, `pgsql`                                                                  |

Les variables d'environnement suivantes sont aussi reconnues pour configurer le déploiement automatique (c'est-à-dire sauter la configuration via le navigateur) de votre instance Joomla :

| Nom de la variable        | Description                                                                          |
| ------------------------- | ------------------------------------------------------------------------------------ |
| `JOOMLA_SITE_NAME`        | Nom du site Joomla                                                                   |
| `JOOMLA_ADMIN_USER`       | Nom complet de l'administrateur Joomla                                               |
| `JOOMLA_ADMIN_USERNAME`   | Nom d'utilisateur de l'administrateur Joomla                                         |
| `JOOMLA_ADMIN_PASSWORD`   | Mot de passe de l'administrateur Joomla                                              |
| `JOOMLA_ADMIN_EMAIL`      | Adresse e-mail de l'administrateur Joomla                                            |
| `JOOMLA_EXTENSIONS_URLS`  | Liste d'URLs séparées par des points-virgules pour installer des extensions Joomla   |
| `JOOMLA_EXTENSIONS_PATHS` | Liste de chemins séparés par des points-virgules pour installer des extensions Joomla |
| `JOOMLA_SMTP_HOST`        | Host SMTP pour les e-mails sortants                                                  |
| `JOOMLA_SMTP_HOST_PORT`   | Port SMTP pour les e-mails sortants                                                  |

### D'autres projets ? Combien de sites puis-je avoir ? {#other-projects-how-many-sites-can-i-have}

Comme nous venons de le voir, nous pouvons lancer plusieurs projets Joomla en même temps sur notre machine et y accéder le plus simplement possible en faisant varier le numéro de port web (`8081`, `8082`, `8083`, ...).

Mais combien puis-je en avoir ? Eh bien, ça dépend juste de votre machine.

Pour information, voici ce que je vois en ce moment sur mon ordinateur Windows (j'utilise Docker Desktop et WSL2).

![Docker desktop](./images/docker_desktop.webp)

Comme vous le voyez, j'ai en fait quatre projets : mon blog actuel (qui tourne aussi sous Docker) et les trois projets Joomla.

Si vous regardez la colonne **CPU (%)**, vous pouvez voir que les projets sont presque endormis. Et c'est normal : une fois la page web affichée, Joomla et MySQL n'ont plus besoin de CPU. La page est affichée, donc ils dorment.

Pour la mémoire, j'ai alloué 20 Go max. à WSL/Docker et en ce moment, mes quatre projets (blog inclus) consomment 3,3 Go au total. Je peux donc démarrer bien plus de projets.

Mais ai-je besoin de travailler sur les trois projets en même temps ? Probablement pas. Alors pourquoi ne pas arrêter, par exemple, le premier et le troisième projet ?

Dans la console, lancez simplement `make stop` dans les dossiers des projets 1 et 3, en exécutant `( cd project_1 ; make stop ; cd ../project_3 ; make stop)`. Nous allons ainsi arrêter (pas supprimer ; juste geler et libérer de la mémoire) notre premier et notre troisième projet.

<Terminal typewriter>
  $ ( cd project_1 ; make stop ; cd ../project_3 ; make stop )
</Terminal>

En revenant sur Docker Desktop, on voit effectivement que nous avons gagné 1 Go de RAM.

![Le premier et le troisième projet sont libérés](./images/docker_desktop_stopped.webp)

<AlertBox variant="note">
Dans notre exemple ici, nous n'avons gardé que le deuxième projet, nous pouvons donc toujours travailler sur `http://127.0.0.1:8082/` mais les deux autres projets (`http://127.0.0.1:8081/` et `http://127.0.0.1:8083/`) ne répondront plus. Nous les avons arrêtés.

Relancez simplement `make up` dans le dossier `project_1` par exemple pour remettre le site en vie. Ou, si vous préférez l'interface graphique, dans Docker Desktop, cliquez juste sur le bouton `Start` :

<Terminal typewriter>$ ( cd project_1 && make up )</Terminal>

![Démarrer un container dans Docker Desktop](./images/docker_desktop_start.webp)

</AlertBox>

## Conclusion {#conclusion}

Trois petits fichiers — `compose.yaml`, `.env`, `makefile` — et `make up` devient toute votre
histoire de déploiement Joomla : installations neuves, sites préconfigurés qui sautent l'assistant
d'installation, et autant de projets isolés (versions différentes de Joomla/PHP/MySQL) que votre
machine peut en supporter, chacun démarré, arrêté ou détruit en une seule commande.

À ce stade, vous vous demandez peut-être : tout ça c'est bien beau, mais j'ai déjà un site Joomla et j'aimerais en faire une sauvegarde puis la restaurer en local avec Docker ; comment faire ?

Si c'est bien votre question, lisez l'article suivant : [Restore a Joomla backup using Docker](/blog/docker-joomla-restore-jpa)
