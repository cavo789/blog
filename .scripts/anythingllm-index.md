# Documentation: AnythingLLM Blog Indexer

## Overview

The `anythingllm-index.sh` script pushes every published blog post into an
[AnythingLLM](https://anythingllm.com/) workspace so the whole corpus can be queried in plain
English, with each answer citing the article it came from. It is incremental: re-run it after
publishing and only new or modified posts are sent.

A byte-identical copy of the script body is published inside the article
`blog/2026/08/17/anythingllm-chat-with-your-docs/files/anythingllm-index.sh`. **Edit one, sync the
other** — see the header of either file for the exact `diff` command.

## Technical Architecture

1. **Discovery:** `find` walks `blog/` for every `index.md` / `index.mdx`, skipping `draft: true`.
2. **Identity:** `slug` and `title` are read from the YAML frontmatter. Because every post is an
   `index.md`, the file is transmitted as `<slug>.md` via curl's `;filename=` — without this every
   citation would read `Source: index.md`.
3. **Metadata:** only three fields reach the model, via the header AnythingLLM prepends to every
   chunk — `title`, `published` and (when prefixed `link://`) `chunkSource`. So `chunkSource` is
   set to `link://<site>/blog/<slug>` to carry the live URL, and the frontmatter `date` is
   appended to the title as `(published YYYY-MM-DD)`, because AnythingLLM's own `published` field
   is the indexing date and cannot be overridden. The workspace system prompt in
   [anythingllm-workspace-prompt.txt](anythingllm-workspace-prompt.txt) tells the model which of
   the two to believe and to format dates as DD/MM/YYYY; re-apply it with
   `POST /api/v1/workspace/blog/update` `{"openAiPrompt": "..."}` if the workspace is recreated.
4. **State:** `.anythingllm-indexed` (gitignored) stores `sha256 \t path \t document-location`.
   Unchanged files are skipped; changed ones have their previous copy deleted before re-upload,
   otherwise the workspace answers from two versions of the same article.

## Prerequisites

| Requirement | Description |
| :--- | :--- |
| **AnythingLLM** | Running and reachable on port 3001. The script probes `localhost` then the Docker bridge gateway `172.17.0.1`, so it works from the host and from inside the devcontainer. |
| **Workspace** | A workspace whose slug matches `ANYTHINGLLM_WORKSPACE` (default: `blog`) must already exist. |
| **API key** | Generated in *Settings → Tools → Developer API*. Read from `$ANYTHINGLLM_API_KEY`, or from the gitignored `.env` at the blog root. |
| **Embedding model** | `nomic-embed-text` pulled in Ollama, with `EMBEDDING_MODEL_MAX_CHUNK_LENGTH` ≤ 2048 — above the model's context length every embedding call fails silently. |
| **CLI tools** | `curl`, `jq`, `sha256sum`. |

## Environment variables

| Variable | Default | Purpose |
| :--- | :--- | :--- |
| `ANYTHINGLLM_API_KEY` | *(required)* | Developer API key; falls back to `.env`. |
| `ANYTHINGLLM_URL` | auto-detected | Override the probe if the instance is elsewhere. |
| `ANYTHINGLLM_WORKSPACE` | `blog` | Target workspace slug. |
| `BLOG_DIR` | `blog` | Root of the posts to index. |
| `STATE_FILE` | `.anythingllm-indexed` | Incremental state. |
| `SITE_URL` | `https://www.avonture.be` | Base URL used to build each article's public link. |

## How to Use

From a devcontainer terminal, the `aiindex` shortcut defined in
`.devcontainer/scripts/interactive.sh`:

```bash
aiindex
```

Or directly, from the root of the blog:

```bash
.scripts/anythingllm-index.sh
```

## Output example

```text
added   docker-php-run-script-or-website
added   keepass-overriding-url
added   welcome
...
248 added, 0 updated, 0 unchanged, 0 failed
```

A run where nothing changed makes a single HTTP call (the workspace lookup) and finishes in well
under a second.
